# SILT Core v0.2.0 — Semantic Architecture

**Planned public release:** 23 September 2026  
**Author:** Gareth Farry  
**Copyright:** © 2026 Gareth Farry  
**Project / publishing identity:** SILT Core

SILT Core v0.2.0 establishes a semantic architecture for moments of encounter between participants and systems grounded in different legal, customary, cultural, private, institutional or technical orders.

Its canonical seam is:

> **Source → Standing → Presentation → evaluation at the encounter**

SILT enables relevant relational legitimacy to become mutually legible without requiring originating orders to collapse into a single ontology or surrender their own sources of authority.

## What changes in v0.2

v0.2 is a substantial semantic revision of the original v0.1 architecture. It removes `Status` as a Core object and rejects a universal `Capacity` primitive. Standing is relational and Source-grounded. Presentation becomes the encounter-specific act or envelope through which a Participant brings the minimum relevant projection of Standing into an encounter. Profile Expression provides bounded encounter conditions without becoming a second architectural spine.

The release also makes several distinctions explicit:

- Technical Capability is not Authority.
- Evidence is not Source or Standing.
- Collective Standing does not imply representational Authority.
- Cryptographic continuity is distinct from semantic continuity.
- Binding is a downstream effect, not a universal Core conclusion.
- Multiple Profile Expressions may coexist without silent precedence or merger.
- Deliberate non-expression is not absence, failure or a fourth evaluation outcome.

Evaluation has exactly three outcomes:

- `SATISFIED`
- `NOT_SATISFIED`
- `INDETERMINATE`

## Conformance evidence

The v0.2 minimal semantic conformance suite contains **4 base encounters and 30 adversarial variants** across:

1. electronic transferable instruments;
2. credential-carried institutional Standing;
3. plural and collective Profile Expressions; and
4. recursive AI-agent delegation.

The repository CI validates the suite against the published JSON Schema and locks the evaluation vocabulary to the three outcomes above.

An experimental, non-normative mapping to Legal Context Protocol is included as an external carrier pressure test. The mapping records bounded semantic loss rather than forcing SILT semantics into the carrier. It did not expose a requirement for a new universal Core object.

## Release boundary

SILT Core is **semantically thick and operationally thin**. Authentication, credentials, key continuity, capability tokens, dynamic authorisation, sessions, access control, policy execution and runtime execution remain downstream unless a semantic distinction cannot otherwise be expressed.

The release does not claim to determine universal legal validity, cultural legitimacy, institutional recognition or the authenticity of Indigenous, customary or collective identity. It makes relevant conditions encounterable without claiming jurisdiction over their originating order.

## Historical implementation material

AUT CISRC remains a **SILT Core v0.1 implementation profile**. It is preserved under v0.1 and is not migrated to v0.2 or included in the v0.2 conformance claim.
