**Description**  
SILT Core v0.2 defines a semantic architecture for encounters between participants, collectives and systems operating under different legal, customary, cultural, private, institutional or technical orders. Its canonical seam is **Source → Standing → Presentation → evaluation at the encounter**. SILT is designed to support mutual legibility without requiring originating orders to collapse into a single ontology or surrender their own sources of authority.

The release distinguishes Source-grounded Standing from credentials or status; Presentation from constitution of Standing; Profile Expression from complete representation of an originating order; semantic Authority from Technical Capability; semantic continuity from cryptographic continuity; and encounter-specific evaluation from universal Binding or compulsory recognition.

SILT Core v0.2 was pressure-tested against four worked encounters covering transferable instruments, credential-carried institutional encounters, plural / collective authority and recursive AI delegation. The accompanying machine-readable conformance material is non-normative test notation rather than a universal SILT wire format.

## Archive discipline

The Zenodo record should archive the tagged release rather than the mutable `main` branch.

The archive description should preserve the distinction between:

- normative SILT Core semantic architecture;
- companion human-readable documentation;
- non-normative conformance test notation;
- historical v0.1 implementation material;
- reference code and implementation artefacts.

The record should not imply that the experimental SILT ↔ LCP mapping is a canonical SILT binding, nor that the AUT CISRC / Vietsch implementation is a native v0.2 implementation.
